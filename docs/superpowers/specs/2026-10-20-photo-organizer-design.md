# 피크닉(Picnic) — 아이폰 사진 검색·정리 앱 설계

- 작성일: 2026-10-20
- 대상 기기: iPhone SE 3세대 (A15, RAM 4GB), 사진 라이브러리 약 123.6GB (3만~6만 장 추정)
- 사용 범위: 본인 아이폰 1대에서 개인용으로 사용 (앱스토어 배포 없음)
- 앱 이름 "피크닉"은 가칭이며 언제든 바꿀 수 있다.

## 1. 목표

갤럭시 갤러리처럼 아이폰 사진을 **한국어 단어로 검색**하고, 용량을 차지하는 **불필요한 사진을 골라 정리**한다.

성공 기준:
1. "강아지", "바다", "제주", "영수증", "2023년 8월", 사진 속 글자(간판·문서)로 검색해서 해당 사진이 나온다.
2. 흐린 사진, 비슷한·중복 사진, 스크린샷, 영수증·문서, 큰 동영상을 탭별로 모아 보고 골라서 지울 수 있다.
3. 각 정리 탭에 예상 확보 용량이 표시된다.
4. 앱 자체 저장 용량은 사진 5만 장 기준 60MB 이하.
5. 사진은 기기 밖으로 나가지 않는다 (지명 변환을 위한 좌표 조회만 예외).

범위 밖 (이번 버전):
- 문장형 자연어 검색 ("해변에서 웃는 아이") — 대형 임베딩 모델 필요
- 인물(얼굴)별 검색 — PhotoKit이 인물 정보를 제공하지 않음
- 앱의 자동 삭제 — 삭제는 항상 사용자가 고르고 시스템 확인을 거친다

## 2. 빌드·설치 방식 (무료, Mac 없음)

- 개발 PC는 Windows. Xcode 프로젝트 파일은 직접 작성하지 않고 **XcodeGen의 `project.yml`** 로 정의한다.
- **GitHub Actions macOS 러너**에서 `xcodegen generate` → 단위 테스트(시뮬레이터) → 서명 없는 `.ipa` 빌드 → 아티팩트로 업로드한다.
- 저장소는 공개(public)로 둔다. macOS 러너 시간 제한이 없고, 저장소에 개인 사진·개인정보는 들어가지 않는다.
- 사용자는 `.ipa`를 내려받아 Windows에서 **AltStore(AltServer)** 또는 **Sideloadly** 로 무료 Apple ID 서명 후 설치한다.
  - 무료 Apple ID 서명은 7일간 유효하다. AltStore는 같은 Wi-Fi에서 자동 갱신한다.
  - 아이폰에서 설정 → 개인정보 보호 및 보안 → 개발자 모드를 켜야 한다.
- 나중에 유료 개발자 계정으로 바꾸면 같은 코드로 TestFlight 배포가 가능하다.
- 최소 지원 iOS: **18.0** (SE 3세대는 iOS 18 이상 지원. `VNCalculateImageAestheticsScoresRequest`를 쓰기 위함).

## 3. 전체 구조

```
PicnicApp (SwiftUI)
├── Library      PhotoKit 접근: 권한, 에셋 목록, 썸네일 요청, 변경 감지, 삭제
├── Analysis     에셋 1장 → AnalysisResult (Vision·Accelerate, 순수 계산)
├── Indexer      분석 작업 큐: 최신순 처리, 중단·재개, 진행률
├── Places       좌표 → 한국어 지명 (캐시 + 속도 제한)
├── Store        SQLite(GRDB) 저장소: 스키마, 쿼리
├── Search       한국어 질의 해석 → Store 쿼리
├── Cleanup      정리 후보 산출: 흐림, 비슷함, 스크린샷, 문서, 큰 동영상
├── Lexicon      Vision 영어 라벨 → 한국어 단어/동의어 사전 (JSON 번들)
└── UI           탭(검색·정리·설정), 디자인 시스템
```

각 모듈의 경계:
- **Analysis** 는 `CGImage`(+메타데이터)를 받아 결과 구조체를 돌려주는 순수 함수 묶음이다. PhotoKit·DB를 모른다 → 테스트 이미지로 단위 테스트 가능.
- **Store** 만 SQL을 안다. 다른 모듈은 Store의 Swift 메서드만 호출한다.
- **Library** 만 PhotoKit을 안다. 테스트에서는 프로토콜로 대체한다.
- **Search**, **Cleanup** 은 Store에서 읽기만 한다.

외부 의존성: GRDB.swift (SPM) 1개. 나머지는 애플 기본 프레임워크(Photos, Vision, Accelerate, CoreLocation, SwiftUI).

## 4. 데이터 모델 (SQLite)

`asset` — 사진/동영상 1개당 1행
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | TEXT PK | `PHAsset.localIdentifier` |
| media_type | INT | 사진/동영상 |
| created_at | REAL | 촬영 시각 |
| lat, lon | REAL? | 위치 |
| place_id | INT? | `place` 참조 |
| is_screenshot | INT | `mediaSubtypes.photoScreenshot` |
| file_size | INT | 원본 바이트 수 (`PHAssetResource`의 fileSize) |
| sharpness | REAL? | 라플라시안 분산 기반 선명도 |
| aesthetic | REAL? | 미적 점수 (-1~1) |
| is_utility | INT? | 애플 판단 "유틸리티 이미지"(문서·영수증·캡처류) |
| dhash | INT? | 64비트 차이 해시 |
| analyzed_version | INT | 분석 알고리즘 버전 (0 = 미분석) |

`label` — (asset_id, keyword, confidence). Vision 분류 결과 중 신뢰도 0.3 이상 상위 10개.

`ocr` — (asset_id, text). 인식된 글자를 공백으로 이어 붙인 정규화 문자열. 글자가 없으면 행 없음.

`place` — (id, grid_key, country, admin, locality, sub_locality, name). `grid_key`는 위경도를 소수 둘째 자리(약 1km)로 반올림한 값.

`similar_group` — (group_id, asset_id, is_best). 비슷한 사진 묶음과 추천 보존 사진.

`meta` — 키/값 (마지막 분석 시각, 변경 토큰 등).

예상 크기: 5만 장 기준 약 25~45MB. 썸네일은 저장하지 않는다 (`PHCachingImageManager` 사용).

## 5. 분석 파이프라인

에셋 1장 처리 (사진):
1. `PHImageManager`로 **512px 미리보기**를 요청한다 (`isNetworkAccessAllowed = true`, 저화질 허용). iCloud 원본은 받지 않는다.
2. 한 번의 `VNImageRequestHandler`로 다음 요청을 함께 수행한다.
   - `VNClassifyImageRequest` → 라벨
   - `VNRecognizeTextRequest` (`recognitionLanguages = ["ko-KR", "en-US"]`, `.accurate`) → 글자
   - `VNCalculateImageAestheticsScoresRequest` → `overallScore`, `isUtility`
3. Accelerate(vImage)로 그레이스케일 → 라플라시안 → 분산 = `sharpness`.
4. 9×8 축소 그레이스케일로 `dhash` 계산.
5. 결과를 한 트랜잭션으로 저장하고 `analyzed_version`을 갱신한다.

동영상은 이미지 분석을 생략하고 메타데이터(크기·날짜·위치)만 저장한다.

OCR 비용 절감: `.fast`로 먼저 글자 존재 여부를 보고, 글자가 있을 때만 `.accurate`로 다시 인식한다.

## 6. 인덱서 (진행 방식)

- 처음 실행: 전체 에셋 메타데이터(날짜·위치·크기·스크린샷 여부)를 먼저 빠르게 저장한다 → 큰 동영상·스크린샷 탭과 날짜 검색은 바로 사용 가능.
- 이후 `analyzed_version` 이 현재 버전보다 낮은 에셋을 **최신순**으로 2개씩 동시에 분석한다.
- 앱이 화면에 있는 동안만 진행한다. 백그라운드로 가면 현재 사진까지만 마치고 멈춘다. 다음 실행 시 이어서 진행한다.
- `PHPhotoLibraryChangeObserver`로 새 사진·삭제된 사진을 반영한다.
- 기기가 뜨거워지면(`ProcessInfo.thermalState` ≥ `.serious`) 일시 정지하고 화면에 알린다.
- 진행 중에는 화면 꺼짐 방지 옵션을 제공한다 (설정에서 켜고 끔, 기본 켬).
- 예상 속도: SE 3에서 장당 약 0.2~0.4초 → 5만 장 약 3~6시간.

## 7. 지명 변환 (Places)

- 좌표를 `grid_key`(약 1km 격자)로 묶어 격자당 1번만 조회한다.
- `CLGeocoder` 역지오코딩, 언어 `ko_KR`. 요청 간격 1.2초 이상, 실패 시 지수 백오프.
- 사진 분석과 별도 큐로 돈다. 인터넷이 없으면 건너뛰고 나중에 다시 시도한다.
- 저장 필드: 국가, 시·도, 시·군·구, 동·읍·면, 장소명. 검색은 이 필드들을 모두 대상으로 한다.

## 8. 검색

- 질의를 공백으로 나눈 각 단어가 **모두** 맞는 사진을 찾는다 (AND).
- 단어 하나는 다음 중 하나라도 맞으면 일치한다 (OR):
  1. **사물·장면:** Lexicon에서 한국어 단어 → 영어 라벨 목록으로 바꾼 뒤 `label.keyword` 일치. 예: "강아지"/"개"/"멍멍이" → `dog`, `puppy`.
  2. **글자:** `ocr.text LIKE %단어%` (대소문자 무시).
  3. **지역:** `place`의 각 필드 `LIKE %단어%`. "제주" → 제주특별자치도.
  4. **날짜:** "2023", "2023년", "8월", "2023년 8월", "작년", "올해" 패턴을 기간 조건으로 바꾼다.
  5. **특수어:** "스크린샷", "캡처", "동영상", "영상", "흐린" → 해당 플래그 조건.
- 결과는 최신순으로 정렬하고, 맞은 이유(사물/글자/지역/날짜)를 작은 칩으로 표시한다.
- 검색창 아래에 최근 검색어와 추천어(라이브러리에서 많이 나온 라벨·지명 상위 8개)를 보여 준다.
- 5만 장에서 LIKE 검색은 100ms 안팎이므로 전문 검색 인덱스(FTS)는 쓰지 않는다.

Lexicon: Vision 분류 라벨 전체(약 1,300개)에 대해 한국어 대표어와 동의어를 담은 JSON. 영어 라벨 이름으로도 검색할 수 있다.

## 9. 정리 기능

| 탭 | 후보 조건 | 기본 선택 |
|---|---|---|
| 흐린 사진 | `sharpness` < 임계값(라이브러리 하위 분포 기준, 기본 하위 5%) 그리고 스크린샷 아님 | 모두 선택 |
| 비슷한 사진 | 아래 그룹핑 결과 | 그룹마다 추천 1장 제외하고 선택 |
| 스크린샷 | `is_screenshot = 1` | 선택 안 함 |
| 영수증·문서 | `is_utility = 1` 그리고 (OCR 글자 수 ≥ 30 또는 라벨에 document/receipt/text 계열) 그리고 스크린샷 아님 | 선택 안 함 |
| 큰 동영상 | 동영상, 크기 내림차순 상위 | 선택 안 함 |

비슷한 사진 그룹핑:
1. 사진을 촬영 시각 순으로 정렬하고, 3분 이내 연속 사진끼리 후보 쌍을 만든다.
2. `dhash` 해밍 거리 ≤ 10 이면 후보로 남긴다. 거리 ≤ 3 이면 바로 "중복"으로 묶는다.
3. 남은 후보 쌍만 `VNGenerateImageFeaturePrintRequest` 로 그때그때 거리를 계산한다 (저장하지 않음). 기준 거리 이하이면 "비슷함"으로 묶는다.
4. 그룹 내 추천 보존 사진 = `sharpness` × `aesthetic` 이 가장 높은 사진.

공통:
- 각 탭 상단에 후보 수와 **예상 확보 용량**(선택 항목 `file_size` 합)을 표시한다.
- 삭제는 `PHAssetChangeRequest.deleteAssets` → 시스템 확인 창 → 사진 앱의 '최근 삭제된 항목'으로 이동(30일 복구 가능).
- 사진을 길게 누르면 크게 보기, 좌우로 넘기며 비교할 수 있다.

선택 조작 (정리 탭 전체와 검색 결과에 공통):
- 상단 도구막대에 **전체 선택** / **전체 선택 해제** 버튼을 항상 표시한다. 상태에 따라 하나의 버튼이 두 동작을 번갈아 하지 않고, 두 버튼을 따로 둔다.
- 비슷한 사진 탭은 그룹 머리글마다 **그룹 전체 선택 / 해제** 버튼, 탭 상단에 **추천만 남기고 모두 선택** 버튼을 둔다.
- **드래그 선택:** 사진 위에서 손가락을 가로 방향으로 움직이기 시작하면 선택 모드로 들어가고, 이후 위아래로 움직여도 지나간 사진이 연속(시작 칸~현재 칸 범위)으로 선택된다. 세로 방향으로 시작하면 일반 스크롤이다 (사진 앱과 같은 방식).
  - 첫 칸이 선택 안 된 상태였으면 범위를 "선택", 선택된 상태였으면 범위를 "해제"한다.
  - 손가락을 되돌리면 범위가 줄어들고, 범위 밖으로 벗어난 칸은 드래그 시작 전 상태로 돌아간다.
  - 손가락이 화면 위·아래 가장자리 60pt 안에 있으면 자동 스크롤한다.
  - 칸이 바뀔 때마다 가벼운 햅틱을 준다.
- 하단 고정 바: "n장 선택 · 1.2GB" 와 삭제 버튼.
- "이 사진은 정리 대상에서 제외" 기능: 제외 목록은 `meta`/별도 테이블에 저장한다.

## 10. 화면 구성과 디자인

### 탭 구조
1. **검색** — 큰 검색창, 추천어 칩, 최근 검색어, 결과 그리드(3열).
2. **정리** — 상단 "정리하면 n GB를 비울 수 있어요" 카드, 아래 5개 정리 카테고리 카드(아이콘·장수·용량).
3. **설정** — 분석 진행률, 앱 사용 용량, 색인 초기화, 화면 꺼짐 방지, 사진 접근 권한 안내.

분석이 끝나지 않았으면 검색·정리 화면 상단에 얇은 진행 배너("사진 12,340 / 48,210장 분석 중")를 표시한다.

### 디자인 방향: 2030 여성 타깃 — "부드럽고 정돈된 감성 다이어리"
- **색:** 크림 배경(#FBF7F2), 메인 포인트 더스티 로즈(#E58F9E), 보조 세이지 그린(#A8C3A0)·라벤더(#BDB2E0)·버터 옐로(#F6D98B). 정리 카테고리마다 파스텔 색을 하나씩 준다. 텍스트는 순검정 대신 웜 차콜(#3B3335).
- **다크 모드:** 따뜻한 짙은 갈색 배경(#1E1A1B), 포인트 색은 채도를 조금 낮춰 유지.
- **글꼴:** 시스템 SF Pro Rounded(둥근 서체), 한글은 시스템 기본(Apple SD 산돌고딕 Neo). 큰 제목은 굵게, 본문은 여유 있는 줄 간격.
- **모양:** 모서리 반경 큰 카드(20~24pt), 아주 옅은 그림자, 넉넉한 여백. 사진 그리드는 2pt 간격과 작은 모서리 반경.
- **아이콘:** SF Symbols의 채움형(.fill) + 파스텔 원형 배경.
- **말투:** 친근한 해요체. 예) "흐릿한 사진 23장을 찾았어요", "정리하면 1.2GB가 생겨요 ✨".
- **움직임:** 카드 누를 때 살짝 눌리는 스프링 효과, 삭제 완료 시 확보 용량 숫자가 올라가는 애니메이션과 가벼운 햅틱.
- **앱 아이콘:** 더스티 로즈 배경에 크림색 사진 프레임 + 작은 하트/반짝임 모양.

## 11. 오류·예외 처리

| 상황 | 처리 |
|---|---|
| 사진 접근 거부 | 안내 화면 + 설정 앱으로 이동 버튼 |
| "선택한 사진만" 허용 | 허용된 사진만 분석하고 상단에 전체 접근 권장 배너 |
| iCloud 미리보기 받기 실패 | 해당 사진을 건너뛰고 표시해 둔 뒤 나중에 다시 시도 (최대 3회) |
| 지명 조회 실패·제한 | 백오프 후 재시도, 지명 없이도 다른 검색은 동작 |
| 삭제 확인 창에서 취소 | 아무것도 바꾸지 않음 |
| 기기 과열 | 분석 일시 정지 + 안내 |
| DB 손상·스키마 변경 | 색인을 지우고 다시 분석 (사진에는 영향 없음) |

## 12. 테스트

- **단위 테스트 (GitHub Actions 시뮬레이터에서 실행):**
  - Analysis: 선명한/흐린 테스트 이미지의 sharpness 대소, dHash 결정성·해밍 거리, 동일 이미지 거리 0.
  - Search: 질의 해석 (날짜 패턴, 동의어 확장, AND/OR 조합) — 메모리 SQLite 사용.
  - Cleanup: 그룹핑 로직(시각 창, 해시 임계값, 추천 사진 선택) — 가짜 데이터 사용.
  - Lexicon: JSON 로드, 모든 항목에 한국어 대표어 존재.
- **실기기 확인 (사용자):** 설치 후 체크리스트 — 권한, 진행률, 검색어 10개, 정리 탭 5개, 삭제·복구 확인.

## 13. 배포 계획

### 1단계: 개인용 (이번 구현 범위)
2절의 무료 사이드로드 방식으로 본인 아이폰에서 사용·검증한다.

### 2단계: 앱스토어 출시 (검증 후 별도 작업)
- 애플 개발자 프로그램(개인, 연 $99) 가입. 업로드는 GitHub Actions + App Store Connect API 키(fastlane)로 하므로 Mac이 필요 없다.
- 수익 모델(안): 검색·정리 후보 보기는 무료, 삭제는 하루 일정 장수까지 무료, **평생 이용권 1회 결제**로 무제한. StoreKit 2 사용.
- 심사 대응: 사진 정리 앱은 경쟁이 많은 분야라 가이드라인 4.3(b) "포화 카테고리" 반려 위험이 있다. **한국어 검색 + 사진 속 글자 검색 + 기기 내 처리(데이터 수집 없음)** 를 차별점으로 내세운다.
- 1단계부터 지켜 둘 것 (나중에 출시를 쉽게 하기 위해):
  - 비공개 API를 쓰지 않는다.
  - Info.plist 권한 설명 문구를 정식으로 작성한다.
  - `PrivacyInfo.xcprivacy`(개인정보 매니페스트) 포함, "수집 데이터 없음".
  - 번들 ID를 고정한다 (`com.<사용자>.picnic` 형태, 구현 시 확정).

### 토스 미니앱(앱인토스): 부적합
앱인토스의 앨범 API는 사용자가 고른 사진만(기본 10장) 받을 수 있고, 날짜·위치 정보 제공과 삭제 기능이 없다. 라이브러리 전체 검색·정리라는 이 앱의 핵심 기능을 구현할 수 없으므로 대상에서 제외한다.
